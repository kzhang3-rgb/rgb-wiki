# imozuru：芋づる式地把未知领域挖到原文的 Claude Code 技能

> 记录一个"**不给你摘要、只给你原文位置**"的调研技能（`MaryCache/imozuru`）：它先建"术语 / 关键人物 / 集散媒体"的地图，再顺着引用、链接与作者**一路挖到原文**并保存；回答时**只标注"哪个文件第几行"**，不替你下结论。三件最值得记的事：① 方法论取自**图书馆情报学**（Bates 的 berrypicking、Ellis 的探索行为模型、Kuhlthau 的探索过程研究）；② **2.0 起加入给人读的详细报告（Lv1–Lv3）与调查看板**；③ 引用**由脚本逐字机械核对**，对不上就不生成页面。

## 核心结论

**一句话定位（README 自述）**：imozuru 是一个把**未知领域一路挖到原文**的 Claude Code 技能；它要解决的问题是"**直接问 LLM，它多半只读搜索结果前几条就给你一份摘要**"——摘要是快了，但**判断所需的细节会被抹掉**，而在你还没掌握领域用语之前，**连搜索词都选不出来**。

**① 它是"反摘要"的。** 技能的核心动作是：先锁定**领域的术语、处在中心的人、知识聚集的媒体**，再顺着引用 / 链接 / 作者一路挖到原文；**收集到的原文不摘要**，只在回答里指出"**哪个文件的第几行**"作为依据。AI 用原文当判断材料，**人再去看那个位置的原文来验证判断**。（对应 README 引用的 Kuhlthau（1991）：**调查初期就详细归纳会诱发过早收束（premature closure）**，所以 imozuru 只在**停止挖掘之后**才写解说。）

**② 它有两条可核实性设计，都落在脚本里。**
- **抜き書き（摘录页）**：按调研论点把原文相关段落切出来排成一页——切的时候**容易混进改写**，于是 `report.py` 会**逐行核对"切出来的这句是否原封不动在原文指定行里"，哪怕错一个词也不生成页面**。
- **详细报告（2.0 新增）**：按读者水平分 **Lv1（无前提）/ Lv2（懂邻近领域）/ Lv3（本领域专家）** 三篇，**每一句解说都要挂上原文引用作依据**，`digest.py` 用同一套机制核对，**只要有一句没有依据就不生成页面**。

**③ 停止条件是明写的、借了论文的。** 两条：**论点都挂上了原文位置**（借 Roh 与 Han（2026）的 HALT）与**饱和**（两名检索子代理列出的资料 **7 成以上**已在地图里；借 Kastner（2007）的"两次独立探索重叠估计总量"，**7 成是试验出的暂定值**）。另外为防"论点都变成不用读原文就能答"，要求**至少一个论点原样包含请求措辞、过半论点必须读原文才答得出**。

**个人判断（未验证）**：这个项目的价值不在"搜得全"，而在**把"AI 不许替你把话说满"写成了可校验的机制**——原文存本地、结论只给位置、引用逐字比对。代价是**慢、耗 token、且需要用户自己去看原文**，它不适合"我要一段能直接用的概述"。

## 它与"直接问模型"的区别（README 自述）

| | 不用技能直接问 | imozuru |
| --- | --- | --- |
| 读什么 | 搜索结果前几条 | 顺着引用 / 链接 / 作者挖到**原文** |
| 给什么 | **摘要** | **不摘要**，只给"哪个文件第几行" |
| 谁能验证 | 难 | 用户可**照位置读原文**核对判断依据 |
| 何时下结论 | 立刻 | 满足停止条件后才写解说（防过早收束） |

## 工作流（六步 + 一个旁路）

1. **写问句与调研论点**：Claude 先写出问句，以及答它所需的 **3–6 个论点**。
2. **建地图**：用**两条换了搜索方式的检索子代理**（Web 检索）收集**术语 / 人 / 媒体**，汇总进 `map.md`。
3. **溯源**：顺着参考文献、被引、作者一路挖；**论文稀少的领域**改为追文章里的链接与"参考了某某的文章"这类记述。
4. **存原文**：找到的原文存进 `sources/`；**404 或要求登录的页面会被剔除**（不收纳）；每份原文会**打来源印记**——`〔论文〕`（同行评审 / arXiv 预印本）、`〔本人〕`（当事人自述的经历）、`〔観察〕`（观察他人作品的记录）、`〔まとめ〕`（他人知识的整理转述）、`〔公式〕`（工具/产品官方文档），**信哪个由用户定**。
5. **收束**：满足停止条件（论点都挂上原文 **或** 饱和）后停工。
6. **产出给人读的两层**：摘录页（論点 × 原文）与详细报告（Lv1–Lv3 解说 + 全量检索记录）。

**旁路——监视模式** `/imozuru watch <話題>`：与上面的流程**独立**，把挖掘中发现的信息源（Qiita / Zenn 标签、note、YouTube、博客、arXiv）的**新文章用 RSS 收集并排出来**。

**产物落盘结构**（默认 `~/research/<話題>/`）：`map.md`（问句 / 论点 / 术语 / 人 / 媒体 / 原文表 / 下一步线索）、`log.md`（每轮找什么、出什么、判断与理由）、`sources/`（原文）、`extracts.json`、`report.html`、`queries.jsonl`（逐个检索词的全量命中）、`fetch-log.jsonl`（URL 与 OK / FAIL）、`digest.json`、`digest.html`。

**看板（2.0 新增）**：`dashboard.py` 把 `~/research` 下所有调查汇总成 `index.html`——主页给**停止理由、原文来源、追引用/链接的周回数**等统计；侧栏可切话题，话题详情里能直接读详细报告与摘录；侧栏搜索覆盖**题名 / 疑问 / 术语 / 人物 / 媒体**（支持假名与罗马字）。

## 使用前需要注意

- **问句会作为检索词发到外部**：README 明确警告——检索子代理做 Web 检索，**问题的内容会以检索词形式送到外部**，**涉及机密信息或个人数据的调研不要用它**。
- **不绕过付费墙**：README 写明**不使用规避手段获取付费论文**，取不到的会**如实报告"没拿到"**。
- **保存的原文属"自用副本"**：README 要求**不要再分发**已保存的原文。
- **SSRF 防护是默认开的，且有已知局限**：`fetch.py` **不抓 http(s) 以外的 URL，也不抓本机/内网地址**（127.0.0.1、192.168.x.x 等），防止搜索结果里塞恶意 URL 去读本机服务；**但**某些 VPN / 代理会把外部站点名解析到内网，这时什么都抓不到，**只有这种情况**才设 `IMOZURU_ALLOW_PRIVATE=1` 取消该检查；README 自己也承认**经代理时按名字解析的路径无法防 DNS rebinding**。
- **手机看图要设口令**：`dashboard.py --serve` **只监听 127.0.0.1**，需配合 `IMOZURU_SERVE_TOKEN`（16 字符以上，不设则每次启动都变）与 Tailscale 之类的自机器中继；README 给了 `https://<PC名>.<tailnet>.ts.net/?k=<口令>` 的访问方式。
- **方法论的"出典"是可查的（这是它的特色而非免责）**：每条例规来自哪篇论文的哪里，README 指向 `references/theory.md`；**这些引用关系我未逐条回原文核对**。
- **我只读了 README 与文件清单及元数据**：**未安装插件、未跑 `report.py` / `digest.py` / `dashboard.py`、未做任何真实调研**；"逐字核对 / 不生成页面"等行为均来自文档自述，**未复现**。
