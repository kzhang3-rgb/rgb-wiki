# FlyCoder：用果蝇连接组控制 CSS

> 记录一个闭环实验，以及它把"哪些是真的、哪些是造出来的"写得非常清楚的做法。

- 状态：草稿
- 最近核验：2026-10-30（阅读仓库 README、目录结构与文档，未安装运行）
- 适用范围：Python；含浏览器仪表盘与 3D 可视化；依赖 GPU 相关依赖文件与 fly.ai 的 FlyBrain

## 核心结论

一个概念实验：**用果蝇的神经连接组驱动一个 CSS 布局任务**——让一个方块居中。

它建在 fly.ai 的 `FlyBrain` 之上，**不重训、不改写** MaleCNS 连接组，权重保持冻结。真正新增的是一个"实验性接口"：CSS 视口、映射到真实视觉投射神经元的编码器、把下行神经元活动当作动作光标、实时仪表盘，以及同一组控制信号的三维具身可视化。

作者在 README 里反复强调边界，甚至单独写了一行："FlyCoder does **not** claim that Drosophila neurons understand CSS."（不声称果蝇神经元懂 CSS。）

## 它实际做了什么

闭环流程（README 的图）：

```
CSS 布局误差
  → 实验性编码器（映射到 LC10a / LPLC1 / LC4 / LPLC2）
  → MaleCNS 派生的 FlyBrain（166,700 个神经元、25,582,938 条过滤后连接）
  → 下行神经元 DNa02 / DNp01 / DNg100 / MDN
  → 实验性动作控制器（LEFT / RIGHT / COMMIT / REJECT）
  → CSS 操作
  → 浏览器预览
  → 实验性奖励（到中心的距离改善）
  → 回到最前面
```

关键点：**连接组的权重是冻结的**。新增的部分是"输入怎么进去、输出怎么解释"——也就是编码器与解码器，以及外挂在连接组**之外**的一个动作选择器（含 Q 表与空闲提交回退）。

## 模块结构

| 模块 | 职责 |
| --- | --- |
| `coder_env.py` | 1920×1080 视口、CSS 栈、布局、距离奖励 |
| `encoder.py` | 布局误差 → 注入 LC10a / LPLC1 / LC4 / LPLC2 |
| `flybrain.FlyBrain` | 冻结的 MaleCNS LIF 仿真 |
| `decoder.py` | 下行神经元组 → LEFT / RIGHT / COMMIT / REJECT |
| `selector.py` | 动作光标；实验性 Q 值与空闲提交，**位于连接组之外** |
| `experiment.py` | 闭环主流程；仪表盘快照仅用于显示 |
| `dashboard/` | 空间连接组 WebGL 视图 + 过程化 3D 果蝇 + 编辑器与预览 |

## "什么是真实的、什么是实验性的"

这是这份 README 最值得学的地方——它用一张表把每个组件标成"真实数据派生"或"实验性"，毫不含糊：

| 组件 | 状态 |
| --- | --- |
| MaleCNS 神经元身份 | 真实数据集派生 |
| FlyBrain 使用的连接关系 | 真实 MaleCNS 派生连接 |
| FlyBrain 神经动力学 | **简化的 leaky integrate-and-fire**（非生物物理细节） |
| LC10a / LPLC1 / LC4 / LPLC2 的输入映射 | 实验性 |
| DNa02 / DNp01 / DNg100 / MDN 活动 | 真实仿真脉冲 |
| 把这些脉冲解读为"在编码界面状态" | 实验性 |
| CSS 动作的含义 | 实验性 |
| 奖励（到中心的距离改善） | 实验性 |
| Q 表 / 空闲提交回退 | 实验性；**不是连接组权重** |
| 空间连接组视图 | 真实胞体坐标 + 抽样真实连边 |
| 完整神经元形态 | **未包含** |
| 3D 果蝇身体 | 可视化 |
| 翅膀键盘交互 | 具身可视化，**不是生物力学** |

作者还额外声明：空间连接组面板是"可视化"而不是"神经元重建"，3D 果蝇只是控制信号的可视化、不是生物力学完整的果蝇仿真；DNa02 的左右性被当作**通用的左右控制通道**，不是"CSS 的左"。

## 使用前需要注意

- **这是概念验证，不是可用工具**：目标是"让方块居中"这一个任务，价值在于演示"真实连接组能接到什么接口上"，不在于产出。
- **神经动力学是简化模型**：用的 LIF 只是脉冲神经元的简化近似，不是生物物理精确仿真。所有"活动"都是这个简化模型的输出。
- **2 次提交、无测试**：仓库只有一次公开发布加一次 gitignore 调整，没有测试、没有 Release 说明、没有 Issue 反馈。依赖它做二次开发要自己承担维护成本。
- **依赖外部项目与 GPU 环境**：建在 fly.ai 的 `FlyBrain` 之上，还单独提供 `requirements-gpu.txt`，说明并非纯 CPU 可跑；我未运行，具体环境要求未验证。
- **演示视频是仓库里的 mp4**（约数 MB），这也是仓库体积的主要来源。
