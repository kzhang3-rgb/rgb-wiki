# nvzhuang：拍片哥女装 AI 服装参考图集与虚拟试穿

> 记录这个"图集 + 换装后端"项目实际交付了什么，以及图集许可、内容尺度与人脸照片流向这三件使用前必须看清的事。未部署后端、未上传照片、未调用任何模型。

- 状态：草稿
- 最近核验：2026-11-03（阅读仓库 README、`docs/CONTENT_REVIEW.md`、`docs/LINUXDO_RELEASE_AUDIT.md` 与 GitHub API 元数据；未克隆、未部署、未试穿）
- 适用范围：前端是纯静态站点，浏览器直接打开即可用；AI 换装需自建 `backend/`（GoFrame v2）并自备模型 API Key，或接本地 ComfyUI

## 核心结论

分两层看：**免费的那层是"图集浏览"**——2,727 套 AI 生成、**人物不入镜**的纯服装参考图（写实 1,407 + 二次元 1,320），纯前端静态驱动，支持中英双向检索、分类筛选、大图查看，开着网页就能用。**要付费成本的那层是"AI 换装"**——上传人像 + 选服装做虚拟试穿，需要自建 Go 后端并配置大模型（或本地 ComfyUI），消耗的是你自己的模型配额。

它比一般"图集仓库"完整得多：**后端把多模型可插拔、限流、额度、图片校验都做了**（Bearer Token + SHA-256 摘要 + 恒定时间比对、CORS 白名单、令牌桶 10 次/分、日额度 100 次、单图 8 MiB、总像素 2000 万上限防解压炸弹）。这部分工程扎实程度超出预期。

**但必须同时看三件事**：图集许可（"AI 生成图片可商用"是项目所有者的声明，原始素材来源是第三方）、内容尺度（项目自评有 393 件属中-高风险分类）、以及**人脸照片会流向你配置的模型服务**。

## 图集这一层

- **规模**：2,727 套 = 写实真人版 1,407 套 + 二次元动漫版 1,320 套，均为 2:3 比例的服装展示图，**人物不入镜**（悬空或模特台展示）。
- **分类**：春 / 夏 / 秋 / 冬 / 内衣 / 派对 / 泳装 / 性感，共 8 类；数据字段保留日文原名（作者称是为兼容原始数据集）。
- **检索**：中文与英文关键词双向可用，中文模式下服装属性会本地化为中文显示。
- **原尺寸 PNG（约 1 GB+）未入库**：仓库只托管优化后的 WebP；`data.js` 里的原寸路径指向未托管的 `png/` 目录。审计报告承认该目录在 GitHub Pages 上返回 404，前端已做"回退下载高清 WebP"处理。**即"下载原尺寸"按钮拿到的是 WebP，不是原始 PNG。**

## 换装这一层（可选，需自建后端）

后端 `backend/` 是 GoFrame v2 服务，把模型作为可插拔配置，同一套接口下可换成：

| 别名 | 模型 | 说明 |
| --- | --- | --- |
| `comfyui` | Qwen-Image-Edit-2511（优先）/ MiniMax H3 | **本地零成本离线方案**，需自备显卡与 ComfyUI；未就绪自动回退 |
| `gemini` | Nano Banana 2 | 作者标注为云端推荐默认 |
| `doubao` | 豆包 Seedream（火山方舟） | 国内可用 |
| `gpt-image` | GPT Image 2 | 兼容 OpenAI 协议，支持中转 |
| `qwen` / `zhipu` / `siliconflow` 等 | 通义万相 / 智谱 CogView / 硅基流动 | OpenAI Images 兼容，配置里加一段即可 |

前端提供"设置中心"：可以把**协议、Base URL、API Key、模型名**存在**当前浏览器**里，随单次请求临时发给后端；也有"本机生成记录"存在 IndexedDB，不上传、不跨设备同步。

## 使用前需要注意

- **图集许可的效力边界**：MIT 覆盖代码没有争议，但"1,407 套服装图集可自由商用"是**项目所有者的声明**，而 README 同时写明图集灵感与原始整理来自第三方（X 账号 `@giaaibusi`）。**这些图是否全部由本项目所有者生成、是否含第三方权利（二次元分类尤其可能涉及角色设计），我未核实，不能只凭这句声明当作可商用保证。** 真要商用时建议自己再核一遍素材来源。
- **内容尺度**：项目自带的内容审查报告给分类做了评级——内衣（199 件）、泳装（54 件）、性感（140 件）共 393 件标为**中-高风险**，作者自己建议"公开宣传只使用春夏秋冬与正装类"。这份自评很坦诚，但也说明**这 393 件在严格审查环境下容易被误判**。
- **人脸照片的数据流向**：AI 换装要上传人像。README 说自定义服装原图"仅保留在当前页面内存中，刷新即清除"、生成结果存本机 IndexedDB、后端不把个人模型配置写入数据库或业务日志——**这些都是项目自述，我未审计代码验证**。实际链路是：照片经你配置的后端，发往你配置的模型服务。**用他人或公开人像前先确认使用权；不要上传你不愿离开本机的照片。**
- **API Key 存在浏览器里**：设置中心把 Key 存本地，适合个人设备；README 自己提示共享设备用完点"清除本地配置"。这是"方便"与"风险"的取舍。
- **后端有 SSRF 防护但不等于绝对安全**：README 说个人 Base URL 默认禁止指向 localhost / 内网 / 保留地址。这是**主动防护的设计**，不代表公开部署后没有其他攻击面——README 另附了 `backend/DEPLOY.md` 的生产加固说明，真要公开部署应照做。
- **184 MB 的仓库**：克隆会慢；如果只想看图集，直接用在线 Pages 更划算。
- **换装效果的演示图是作者挑选的最佳案例**，不代表你的输入都能得到同等效果。
