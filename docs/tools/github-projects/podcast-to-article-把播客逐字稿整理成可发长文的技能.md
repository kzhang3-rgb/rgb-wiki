# podcast-to-article：把播客逐字稿整理成可发长文的技能

> 一句话定位（README 自述）：**"把一期播客的逐字稿，整理成能直接发的长文"**——多人对谈、单人访谈都行，中英文素材都行。它抓的核心矛盾是**换轴**：**逐字稿的轴是"发言人和时间"，文章的轴是"话题和判断"**，这个 skill 做的就是换轴。方法论被压成三条规矩：**拆掉发言人的脚手架、保留事实的颗粒度、留住原话的语气**（"前两条管信息，第三条管人"）；其中**拆脚手架只在一个条件成立时做——几个人说同一件事**，单人对谈里"说话人是唯一的信息源"，反而要尽量原话直译。它**纯 python3 标准库、除 `SKILL.md` 外无任何平台依赖**，只提供两个脚本：`scripts/prep_transcript.py`（字幕清洗）与 `scripts/check_style.py`（成稿自检）。最值得记的是三点：① 它明确点名"直接让模型写"通常会得到**三种坏结果**——记流水账、抽象化丢细节、以及最难发现的**改写过度**；② 它给出**可量化的自检口径**（破折号 / 对举句 / 总结腔 / 序数词小标题 / 动词名词化 / 段首零回指评论，外加**直接引语占比**与**段首自足判断句占比**）；③ 语言规则的数值来自一份**629 篇、95,551 句**的中英对照语料研究，并给出三条**与流行说法相反**的结论。

- 状态：草稿
- 最近核验：2026-11-13（阅读 README 全文（93 行）、`LICENSE` 全文、仓库文件树与元数据；**未 clone、未安装到任何 agent 的 skills 目录、未跑 `prep_transcript.py` 或 `check_style.py`、未用任何逐字稿实测**）
- 适用范围：**面向 AI agent 的技能包**（`SKILL.md` 是给 agent 读的说明书）；README 给的安装示例是 Cola（`~/.cola/skills/`），其它 agent 只需把整个目录放进其 skills / rules 目录并指向 `SKILL.md`；运行环境**只需 python3 标准库**，输入支持 **SRT、VTT**，以及已转成 **md / txt** 的转写稿（带 `**发言人：**` 标记的也能识别）

## 核心结论

1. **问题定义**（README 自述）：直接让模型"把逐字稿写成文章"，通常产出三种东西——**记流水账**（满篇"张三说……李四说……"，像会议纪要）、**抽象化**（数字与细节全丢，换成"行业正在加速"这类很顺但没有新信息的句子）、以及**改写过度**（原话被压成第三人称概述、"他说"被换成陈述句，读不出说话人的样子）。
2. **方法主线**（README 自述）：**换轴 + 三条规矩**——拆脚手架（仅在同题多人时）、保颗粒度、留语气；**单人对谈**则反过来"尽量原话直译、原样保留"。
3. **七步流程**（README 自述）：**清稿 → 要点梳理 → 定主线 → 换轴成文（用原文）→ 人名校准 → 精简 → 自检**；对 agent 只需说一句"这是这期播客的逐字稿，按 Next Token 的格式整理成一篇文章"。
4. **两个可独立使用的脚本**（README 自述）：`scripts/prep_transcript.py`（去时间轴、按说话人合并成段、报统计，`--speakers` 只列说话人）与 `scripts/check_style.py`（成稿自检：AI 痕迹逐条命中数 + 人类基准对照，**兼报直接引语占比（实录体参考 10–28%）与段首自足判断句占比（参考 ≤30%）**）。
5. **实测数据（作者自述）**：一份 **5,730 汉字**的"发言人为轴"原始稿 → **3,703 汉字**的发布稿，**砍掉 35%**，段落 **57 → 47**（口径为本仓库 `check_style.py`）；自检跑出来**破折号 0、对举句 0、总结腔 0、序数词小标题 0、动词名词化 0、段首零回指评论 0**，**只在"一句话概括："那一处提示性冒号上翻车一次**；作者评价"广受好评"。
6. **第二个案例（英文单人访谈，作者自述）**：整理 Invest Like the Best 的一期（Noah Shinn 谈 Instinct，86 分钟）时**第一版犯的正是"改写过度"**（3,600 字、按话题平铺、43 段、每段一句自足判断、全篇直接引语 0 处）；三步改法（**先定一条主线**、**把概述换回原话**、**把每节标题改成能预判内容的句子**）后又返工三次（引号太多 / 过渡句自己攒得太重 / 替嘉宾描述了态度），并发现一处**发言归属错误**；**终稿 2,573 字、直接引语占比 23%（18 处）、段首自足判断句 0%**。
7. **许可证**（`LICENSE` 事实）：**MIT**（`Copyright (c) 2026 冯雷 (MarsWave)`）。

**个人判断（未验证）**：它最有价值的可能不是"帮你写文章"，而是**把"AI 味"拆成了可自查的条目**——`references/style-rules.md` 里每条语言硬约束都附**人类 / AI 实测基准**，`check_style.py` 把"命中数"落成数字。这套"**规则可量化 + 脚本可复核**"的写法，比"多改几遍"更可迁移。但**所有效果数据都来自作者自述的案例**，未做独立复现。

## 能力结构

### 1. 换轴与三条规矩（README）

| 规矩 | 含义 | 触发条件 |
| --- | --- | --- |
| **拆掉发言人的脚手架** | 去掉"张三说 / 李四说"这类发言人框架 | **只在"几个人说同一件事"时做** |
| **保留事实的颗粒度** | 数字与细节不许被抽象成空话 | 始终 |
| **留住原话的语气** | 保留直接引语，不把原话压成第三人称概述 | 单人对谈时"反过来"——尽量原话直译、原样保留 |

README 特别提醒第三种坏结果（**改写过度**）"最不容易发现"。

### 2. 七步流程（README）

清稿 → 要点梳理 → **定主线** → 换轴成文（**用原文**）→ 人名校准 → 精简 → 自检。

### 3. 目录与文件（README + 文件树）

```
SKILL.md                       流程与判据（agent 的主入口）
references/style-rules.md      语言硬约束，每条附人类/AI 实测基准
references/example.md          同一段逐字稿的两次处理，原始稿对照成稿
scripts/prep_transcript.py     字幕清洗
scripts/check_style.py         成稿自检
```

（另有 `README.en.md` 英文说明与 `assets/cover.{html,jpg,png}` 封面素材。）

### 4. 两个脚本的用法（README）

```bash
# 字幕清洗：去时间轴、按说话人合并成段、报统计
python3 scripts/prep_transcript.py 第004期.srt -o 清洗稿.md
python3 scripts/prep_transcript.py 第004期.srt --speakers   # 只列说话人

# 成稿自检：AI 痕迹逐条命中数 + 人类基准对照
# 兼报直接引语占比（实录体参考 10-28%）和段首自足判断句占比（参考 ≤30%）
python3 scripts/check_style.py 成稿.md
```

### 5. 语言规则的三条反直觉结论（README，数值来自对照语料研究）

- **人类用比喻是 AI 的 2.4 倍**——不要为了"像人"而回避比喻。
- **正文设问**：人类每千字 **1.83** 处、AI **0.10** 处，**差 17 倍**——**少写设问才是 AI 味**。
- **句长均匀度 0.87，没有差异**——强行打乱句长没有用。

## 使用前需要注意

- **效果数据是作者自述**：5,730→3,703 字、"广受好评"、自检各项 0、英文案例的 2,573 字与 23% 直接引语占比，**均来自 README 自述，未做独立复现**；两处案例的"质量"评价带有作者主观色彩。
- **它是"技能"而非"应用"**：没有 UI、没有 CLI 主程序，**必须挂到某个 agent 的 skills / rules 目录**使用；README 只给了 Cola 的软链示例，其它 agent "把整个目录放进它的 skills / rules 目录，指向 `SKILL.md` 即可"——**实际兼容性与触发效果依赖具体 agent**。
- **脚本能力边界**：`prep_transcript.py` 只做**清洗与合并**（按说话人合并成段），**不做说话人分离（diarization）**——它假定输入已带说话人标注；`check_style.py` 是**词法/句式统计**，**不代表文章质量**，只报"AI 痕迹命中数 + 人类基准对照"。
- **输入格式**：支持 SRT、VTT 及已转写的 md / txt（带 `**发言人：**` 标记也可识别）；**上游的语音转写不在本仓库范围内**。
- **规则并非本仓库原创**：语言数值来自第三方仓库 `lieflat-less-ai-tone`（MIT）的对照语料研究（**300 篇五模型生成文本 + 329 篇人类写作，629 篇、95,551 句、45,721 段，检验 26 项候选特征**）；引用这些数值时宜注明出处。
- **项目很新且单点维护**：**2026-10-07 创建**、**贡献者 1**、**0 Release**、**ungh `pushedAt` 2026-10-08（创建次日）**；页面 `updatedAt` 2026-11-09 与代码推送时间不同，**引用时间需区分**。
- **版权与发布边界（个人判断）**：素材是他人播客逐字稿、成料是发布稿，**文字权利与引用范围由使用者自行把关**；本仓库只提供改写流程，不处理授权问题。
- **我只读了 README 与 `LICENSE`**：**未 clone、未安装到任何 agent、未跑任一脚本、未用任何逐字稿实测**；上述流程与数据均来自 README 自述。
