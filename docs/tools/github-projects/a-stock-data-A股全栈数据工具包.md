# a-stock-data：给 AI 编程助手用的 A 股全栈数据工具包

> 记录它把三十多个数据源封成一个 Markdown 文件的做法，以及"能不封 IP 就别封 IP"的取数优先级。

- 状态：草稿
- 最近核验：2026-10-30（阅读 README、FAQ 与 GitHub API 元数据，未安装运行、未实际取数）
- 适用范围：Python 3.9+；面向 Claude Code / Codex / OpenClaw 等 AI 编程助手；取数环境需能访问相应数据源（部分源在海外网络下不稳定）

## 核心结论

一个自包含的 Skill 文件（结构化 Markdown + 内嵌 Python），把分散在 **34 个数据源**里的 A 股及相关市场数据，整合成 AI 编程助手可以直接调用的工具集。README 头部标注的形态是 **15 层架构 · 87 个端点 · 34 个数据源 · 零鉴权（iwencai 除外）**。

它要解决的是"取 A 股数据要背一堆接口细节"的问题：腾讯 K 线的分段参数、通达信盘后包的二进制格式、东财研报的 PDF Referer 头、iwencai 的 X-Claw 鉴权、百度股市通的 PAE Header 拼接，全部封装在文件里。

最值得借鉴的不是端点数量，而是**取数优先级的设计**：按"封 IP 风险"给数据源排了序——能用腾讯与交易所官方就不碰东财；东财只用于它独有的数据，且所有请求统一走 `em_get()` 串行限流。主源失效时另有"备用源速查 & 降级策略"可用。

## 数据覆盖（15 类）

行情 K 线 · 研报 · 市场信号 · 资金面/筹码 · 新闻 · 基础财务 · 公告 · 打板 · ETF 期权 · 舆情互动 · 宏观与利率 · 指数与交易日历 · 期货与大宗商品 · 事件驱动 · 可转债。

另有 5 个"备胎"入口（官方龙虎榜、新浪资金流、公告、沪深官方两融、北交所当前行情），主源被封时降级使用。

主要来源大致是：行情走腾讯 / 通达信官网 / 百度 / 新浪；研报走东财 / 同花顺 / iwencai / 新浪；信号与资金面走同花顺 / 东财 / 交易所；新闻走东财 / 财联社 / 华尔街见闻 / 央视网；公告走巨潮；宏观走人民银行 / 统计局 / 中债。

## 数据源优先级（按封 IP 风险排序）

| 顺序 | 来源 | 通道 | 封 IP 风险 | 用途 |
| --- | --- | --- | --- | --- |
| 1（首选） | 腾讯财经 | HTTP | **不封 IP**（K 线单入口约 600 次后限流，已三入口轮换） | 实时价、PE/PB、市值、换手率、涨跌停、指数、ETF、日周月与分钟 K 线 |
| 中段 | 交易所官方 / 新浪 / 百度 | HTTP | 低 | 官方两融、北交所行情、K 线、研报列表等 |
| 4 | mootdx（通达信） | TCP 7709 | 不封 IP | 财务快照、F10「最新提示」 |
| 末位 | 东财（datacenter / push2 / reportapi / search） | HTTP | **中——有风控会封 IP** | 龙虎榜、解禁、两融、大宗、股东户数、分红、资金流、研报 PDF、个股新闻、ST 名单、事件驱动、可转债 |

架构原则：除 mootdx 与 baostock（TCP 客户端库）外全部直连 HTTP API，不经第三方数据封装；东财系接口统一走 `em_get()` 串行限流防封，批量任务需调大 `EM_MIN_INTERVAL`。

## 已经写在 FAQ 里的坑

这个项目的 FAQ 是我见过写得最"怕你踩坑"的一类，很多条来自 Issue 反馈，值得单独摘出来：

- **mootdx 的行情命令 2026-09 起失效**（Issue #52）：逐台实测 10 台服务器，TCP 能连上、财务与除权除息正常，但 **K 线、五档盘口、逐笔成交都返回 0 行**，换版本解决不了。替代方案是腾讯 K 线、通达信盘后包、腾讯逐笔。
- **海外服务器跑 mootdx 会超时**：它走 TCP 直连通达信行情服务器，需要国内 IP 才稳定；官方建议走代理或改用 yfinance。
- **腾讯字段 43 不是 PB**：43 是振幅%，46 才是 PB。作者说是实测校准，"网上大量教程写错了"。
- **东财系 IP 会被封**，且大陆住宅宽带 IP 也会被连接级间歇风控（表现为 `HTTP 000` 或新闻只返回空壳）。对策是等 30–60 分钟、换网络或降频。
- **北交所老号段（`43x` / `83x` / `87x`）基本作废**：实测在市 342 只中 336 只已迁到 `920xxx`。最坑的是老码**不报错**——研报静默返回 0 篇、行情返回定格在迁移日的僵尸报价（与真实价差 17%~100%+）。V3.6.0 起加了 `is_stale` 标志，研报遇老码直接抛 `ValueError`。
- **mootdx 依赖会与 MCP 冲突**：`pip install mootdx` 会把 httpx 降到 0.25.2，而 MCP 要 ≥0.27.1。但因 mootdx 取数走 TCP 二进制协议、运行时不经过 httpx，可以 `pip install --no-deps "httpx>=0.27.1"` 绕过（作者实测 0.11.7 在 httpx 0.28.1 下正常）。
- **V3.0 移除了 akshare**：理由是 akshare 本质是对东财/同花顺/新浪公开 API 的封装，中间层反而增加故障点（版本兼容 bug 等）。
- **不带回测引擎**：只负责取数，回测要交给自己的框架或聚宽；提供了 `to_joinquant()` 做代码格式转换。
- **单文件自包含是有意决策**：为了"拷一个文件就能用、离线可携、便于分发"，明确不做目录化拆分；token 敏感的用户可以放进项目目录按需读取。

## 使用前需要注意

- **我只读了文档与元数据，没有实际取数**：以上端点能力、字段口径、限流策略均来自 README 与 FAQ 自述，真实可用性与数据准确性未验证。
- **本项目分发的是代码，不是数据**：取数时请求的是各网站的前端接口与公开接口，**能否商用、是否违反对方条款，由使用者自行评估**——A 股这侧 README 没有像姊妹项目那样给出合规分级，需要自己判断。
- **"零鉴权"有一个例外**：iwencai 需 API Key 并携带 `X-Claw-*` Headers。
- **抓取时发现版本口径冲突**：本次通过网页渲染抓到的 README 头部写着"6 层架构 · 21 个端点 · 8 个数据源实测"，而 raw 文件与 GitHub API 描述都是 **15 层 · 87 端点 · 34 数据源**。两处相差很大，本文以 raw README 为准，但这条冲突说明**该仓库的自述数字变动频繁**，引用具体数字时应以你实际拉到的版本为准。
- **注意区分"数据"与"投资建议"**：作者免责声明写的是"本项目仅提供数据获取工具，不构成任何投资建议"。
