# ra2：在浏览器里跑红色警戒 2

> 记录它的技术路线（模拟原版 EXE，而不是重写引擎），以及它对版权边界的处理方式。

- 状态：草稿
- 最近核验：2026-10-30（阅读仓库 README、目录结构与文档索引，未安装运行、未导入任何游戏资源）
- 适用范围：浏览器端；本地开发需 Node + pnpm，首次构建 CPU 部分还需 Rust（wasm32）等工具链

## 核心结论

一个把《红色警戒 2》和《尤里的复仇》搬到浏览器里的项目，支持多人联机，另有实验性的 Mental Omega 3.3.6 支持。

它和"用 Web 技术重写引擎"那类方案（如 Chrono Divide）路线不同：**它直接用 v86 做 x86 模拟，配上自制固件和一层 Win32/DirectX 兼容层，运行原版游戏 EXE，但不启动 Windows**。因此它要求玩家自己提供**合法持有**的游戏安装文件，仓库本身不含任何游戏资源。

README 第一行就是"EA has not endorsed and does not support this product."（EA 未背书、不支持本产品。）

## 两个版本的游戏怎么跑起来

1. 准备你自己合法拥有的游戏资源（页面上的"Get resources"指向购买与 MOD 下载链接）；
2. 选择导入压缩包或直接选游戏目录，**必须包含原版可执行文件**（RA2 是 `game.exe`，YR 是 `gamemd.exe`），页面会检查并列出缺失文件；
3. 选择 RA2 或 YR，点"Launch game"；
4. 在原版游戏里走"Single Player → Skirmish"正常开局。

导入的资源保存在浏览器本地，刷新后恢复选择；"Clear cache"只清资源、保留存档与自定义地图。

**多人联机**：大家用同一个可达的 WebSocket relay 地址、同一房间路径、同一游戏版本与 MOD/地图。RA2 与 YR 不能同桌。连接设置会写进页面 URL，改设置前要先退出对局。

## 相比"重写引擎"路线的差异

README 里有一张与 Chrono Divide 的对比表，差异主要来自技术路线的不同：

| 方面 | RA2 VM（本项目） | Chrono Divide |
| --- | --- | --- |
| 核心思路 | x86 模拟 + Win32/DirectX 兼容层，跑原版 EXE | 用 Web 技术重建 RA2 引擎 |
| 原版战役 | RA2 与 YR 战役可运行 | 官方材料中未见相关支持声明 |
| 尤里的复仇 | 支持，含其原版可执行文件 | 未声明完整资料片支持 |
| Mental Omega | 通过自带的 Syringe/Ares，实验性 | 未见 MO 支持声明 |

作者标注了这张表的做法：只依据 Chrono Divide 官方 About/Features 与 `patch-notes.html`，截至 v0.84.0（2026-09-03），于 2026-10-15 复核；并明确写 **"Not confirmed" 不等于不支持**。这种"把比较方法和截止时间写出来"的习惯值得借鉴。

## 实验性的 AI Agent 接入

仓库内置两个技能：`ra2-strategy`（经济、侦察、防守、作战决策）和 `ra2-battle-control`（原版玩家操作、监控与结果确认），通过 `ra2ctl` 共用同一条指令写入通道。

用法是：开发页开一个终端跑 `pnpm ra2ctl serve`，导入资源后点"Connect AI"选通道；再在另一个终端用 Codex CLI 或 Claude Code 连接：

```bash
pnpm ra2agent --agent codex --channel 1
# 或换 Claude Code
pnpm ra2agent --agent claude --channel 1
```

作者说明的边界比较清楚：**观察范围只限当前镜头与原版玩家可见性**（含战争迷雾与隐蔽过滤），动作仍走原版的建造、放置、寻路与战斗规则；默认加入进行中的对局，加 `--quick-start` 才允许在没有对局时开局。前置要求是 RA2/YR 可执行文件必须通过控制接口指令与内存布局检查，**MO 不在覆盖范围内**。

## 使用前需要注意

- **必须自备合法持有的游戏安装文件**：仓库不分发任何游戏安装文件，也不提供破解、注册机、伪造验证结果或绕过原程序保护检查的功能——这句话写在 README 的"Runtime scope"一节里。原程序的安装数据与授权要求仍然适用。
- **版权边界由作者主动划清，但风险来自外部**：项目本身把资源交给使用者提供，并在 README 顶部声明 EA 未背书。即便如此，能否长期公开运营取决于权利方的态度，属于项目无法控制的外部因素。
- **兼容性明确不保证**：作者写"兼容所有版本不作保证"，启动失败时**不会**绕道走替代路径；内存适配会调整部分启动、等待与网络时序，因此执行流并非完全不变（这点作者如实说明了）。
- **公开仓库是快照，演进过程不可审计**：只有 1 次提交（`init OSS`），README 也写了内部使用不推送的 `dev` 分支、外部贡献提交到 `main`。也就是说，从公开仓库看不到开发历史与评审过程。
- **Alpha 阶段的具体限制**：联机需要所有人版本、MOD、地图完全一致；**中途断线不能续局**，只能重开；MO 支持为实验性，启动校验通过不等于战役或联机完全兼容。
- **首次构建有额外工具链要求**：除 Node 与 pnpm 外，还要 Rust（`wasm32-unknown-unknown`）、clang、lld、make、git、Python 3。
