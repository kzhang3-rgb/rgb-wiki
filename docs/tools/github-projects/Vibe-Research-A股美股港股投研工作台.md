# Vibe-Research：A 股 / 美股 / 港股的本地投研工作台

> 它最值得记的不是"能查数据"，而是**把"数字必须有出处"写成了可执行的校验**：报告中找不到出处的数字会被替换成占位符并把该次运行标为不完整；数据缺口一律如实写明，不改写成 0。

- 状态：草稿
- 最近核验：2026-11-02（阅读 README 全文与 GitHub API 元数据，未安装、未运行、未接入任何 AI）
- 适用范围：Windows 11 / macOS / Linux（Node ≥ 22.18、Python ≥ 3.11）；覆盖 A 股、美股、港股；需接入 Claude Code / Codex / WorkBuddy 订阅或兼容 Chat Completions 的模型 API

## 核心结论

Vibe-Research 是一个**跑在自己电脑上的投研工作台**：浏览器界面 + 本机后端，数据、研报、研究记录都存在本地。README 用一句话概括："打开先看指数、自选和持仓盈亏，再复盘盘面、追资讯、研究产业和公司、验证想法，都在同一个页面里完成。"

它的功能面很大（8 个一级栏目），但真正拉开差距的是三件事：

**① 数字出处核对：把"不许编数字"变成机器校验**

对话与报告里的每个数字都要**能在（你发的消息 / 当前页面 / 取到的数据 / 读过的网页 / 此前对话）里找到，或者是回答里写出的算式算出来的**。找不到的只把那个数字换成「（略※）」并注明有几处；报告交付前换成「〔未核实〕」，**该次运行标记为不完整**。README 还把例外写清楚了：日期、年份、编号、指数名、均线天数不核对；写明"假设/情景"的不核对。

它甚至坦白了自己核对的是**"这个数字有没有出现过"，而不是"用得对不对"**——这比含糊地说"我们保证准确"诚实得多。

**② 数据缺口不改写成 0**

这条在 README 里反复出现：持仓算不出就不算并把原因写在「—」下面；行业资金取不到就换备用源并**写明口径**；前两个交易日涨停池没取到就"写明分不出是不是连续，不当成 0"；港美股不披露扣非就把那一格**写明"未获取"**。**缺数据与"值是零"是两个不同的状态**，这一点在同类工具里常常被混掉。

**③ 三级约束，不只靠提示词**

README 明确说"不只依赖提示词"：

| 层 | 组成 | 作用 |
| --- | --- | --- |
| 提示层 | `methodology/constitution.md`（研究宪法）+ `.agents/skills/` + `calc/SPEC.md` | 定义研究纪律与计算函数契约，**所有 AI 来源一视同仁** |
| 执行层 | 受控工具白名单 + 收工检查 | 研究阶段**只开放 5 个受控工具**，订阅 CLI 的**内建工具全部关闭**；产物缺失或校验不过就退回去修 |
| 编排层 | orchestrator + validator + calc + gate | 强制阶段、证据引用、确定性计算与合规边界 |

研究阶段**没有网络、没有 Shell、没有写目录权限**——只能通过受控工具读净化后的运行文件、调用确定性计算、写当前阶段产物。这条把"Agent 乱跑"的空间压得很小。

其他值得记的工程细节：

- **六阶段个股研究**：公司画像 → 财务 → 盈利预期 → 估值 → 风险 → 报告。**报告里每条推断标一档可信度**（已披露证实 / 有依据的推断 / 未核实线索 / 被反证），除"未核实线索"外都要写出证据或计算编号。
- **研究产物落盘**：`report.md`、`evidence.json`、`calculations.json`（派生数字的**计算 DAG**）、`conflicts.json`（**跨来源冲突不静默取舍**）、`manifest.json`、`viewer.html`。
- **防篡改核对**：每次研究结束与每次软件内保存/删除都在本机登记簿 `audit/chain.jsonl` 记指纹；可人工"核对"发现绕开软件的改动，并给出一个可另存他处的**链头**。README 同时坦白：**能改数据的人也能整份重写登记簿**——这条自我限定写得很到位。
- **MCP 接口**：8 个工具（7 只读 + 1 发起研究，发起目前只支持 A 股），可直接在 Claude Code / Codex / Cursor 里取数、发起研究、读报告与证据，"结果和页面里看到的是同一份"。
- **多 Agent 对照**：同一只股票被两家以上 Agent 研究过时，可并排比**研究过程**（取了多少证据、引用多少、几个阶段一次过校验、几条缺口、用多久），并**明确"只比过程，不比结论对错，也不比收益，不打总分不排名"**。
- **持仓按交易流水记**：期初/买入/卖出/分红/送转拆股，按日期重放出持仓、已实现盈亏；成本法可选 FIFO 或移动加权平均；收益率按币种给**时间加权**与**资金加权（XIRR）**两条线。
- **明确不给投资动作**：输出只含数据、分析框架、情景概率和裁决点，**不提供建仓、加减仓、目标价或止损位**。

## 用法要点

安装分源码版与免安装版两条路：

```powershell
# Windows 源码版
git clone https://github.com/simonlin1212/Vibe-Research.git vibe-research-agent
cd vibe-research-agent
scripts\setup-windows.cmd
scripts\start.cmd
```

```bash
# macOS / Linux
scripts/setup
scripts/start
```

启动后打开 `http://127.0.0.1:5930`（页面默认 5930、本机 API 默认 8765；端口被占用会自动换并在终端说明）。**免安装版**（Windows x64 / Apple 芯片 Mac / Intel Mac）在 Releases 里，压缩包自带 Node 和 Python，解压双击启动；**包没有代码签名**，首次打开会被系统拦（Windows 点"更多信息→仍要运行"，macOS 需 `xattr -dr com.apple.quarantine <文件夹>`）。

接入 AI 时**订阅不需要往页面填 key**——直接用本机已登录的 CLI（Claude Code / Codex / WorkBuddy）；模型 API 则填地址、模型名和 key，点"测试并保存"会**先发一次真实对话，成功才生效**。

MCP 接法（在仓库目录里）：

```bash
claude mcp add vibe-research -- node "$(pwd)/orchestrator/src/mcp.ts"
codex mcp add vibe-research -- node "$(pwd)/orchestrator/src/mcp.ts"
```

## 使用前需要注意

- **"内置模型 API 模板都还没用真实 key 实测"**：README 写得非常直白——截至 2026-10-08，各家 Chat Completions 模板**都没跑过兼容矩阵**，界面标"有模板·未实测"。**只有用真实 key 实测过的模板才会标"已实测"**。所以别默认"填上就能用"，可能要自己踩一遍。
- **平台验收范围有限**：README 的验收记录是 **macOS（2026-10-29，v2.2.6）**：后端 1,295 项（1,287 通过 / 8 跳过 / 0 失败）、desktop 351/351、Python 1,476/1,476。但**"Windows 11 未实机验收，Windows 10 未验证"**，CI 里 Windows 只跑选定的跨平台契约测试。**如果你在 Windows 上用，等于替作者做首轮实机验证。**
- **港股/美股六阶段研究的实测面很窄**：README 说 2026-10-09 用 Claude Code 订阅各真跑一只（苹果、腾讯控股），且**港股那次"报告里还有 3 处数字真没标出处"**；**其他 AI 来源还没在港美股上跑过硬测试**。A 股相对成熟。
- **远程访问只支持 macOS / Linux**，且必须用 https 公网地址——否则**页面里填的 API key 会明文传输**。
- **局域网模式不是账号隔离**：README 原话"这是单用户工作台共享，不是账号隔离，网络内能访问端口的人都能操作"，且 **HTTP 不加密，API key 和研究资料可能明文传输**，**不要暴露到公网**。
- **API key 存在浏览器 `localStorage`**：README 自己说明"**不是系统钥匙串，也不承诺加密**"，只建议在可信的个人电脑上用，共享电脑用完要清除。**这不是一个"密钥被我管好了"的方案。**
- **AI 读网页可能经第三方转发**：README 提示读公开网页时**可能经 Jina Reader 转发，目标网址（含查询参数）会发给该服务**；搜索请求也会发给对应搜索服务。**别把带私密令牌或签名下载凭据的网址丢进去。**
- **数据端点是"登记在册"，不等于可用**：README 明确写"端点登记在册不保证第三方服务随时可用；第三方公开数据可能延迟、缺失或有误"。**168 个端点 / 35 层是覆盖面，不是可用性保证。**
- **迭代速度很快、边界在移动**：2026-07 创建、2026-11 已到 v2.2.6，且 README 里大量"[当前边界]"类说明（Mac 客户端已撤下、v1 升级要点等）。**读到的结论有保质期。**
- **免责声明**：项目只产出研究数据、分析框架、情景概率与裁决点，**不提供投资动作建议**；第三方数据可能延迟、缺失或有误，**使用者自行核实并承担决策责任**。
- **我只读了 README 与元数据**：未安装、未接 AI、未跑过任何研究与回测；**上面所有"校验机制有效""拦截率如何"的说法都来自作者自述**（README 提到随机造的数字被误认成有出处 11/2700 ≈ 0.41%，也属自述数据）。

## 什么时候会再看

- 需要**一个本地运行、数据不出本机的投研工作台**，且在意"数字必须有出处"时：这套"出处核对 + 缺口如实标注 + 计算 DAG + 跨来源冲突保留"的组合，在同作者的数据包之上补了完整闭环。
- 想参考**"怎么约束 AI 不乱编数字/不乱执行"**时：**三级约束 + 5 个受控工具 + 交付前占位符替换 + 运行标不完整**，是一套可直接借鉴的落地写法。
- 想参考**"多 Agent 横向比较"怎么设计**时：只比过程、不比结论、不打分不排名，并把"取数范围不同不能直接比"写在前面。
- 想参考**"本地登记的防篡改"怎么写**时：指纹链 + 可另存链头 + **主动声明它防不住谁**，这套自我限定比"我们做了防篡改"更有信息量。
- 需要**Windows 原生跑（不装 WSL）**的量化/投研工具时：这是明确支持 Windows 原生脚本链的一个样本，但同时要记得它**未在 Windows 实机验收**。
