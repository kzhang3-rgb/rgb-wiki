## 核心结论

这份仓库的价值在于**策展结构**，不在于内容本身。它自己说得很清楚：投资自己任何时候都划算，而这是作者个人整理的、用来"在 2026 年及以后成为一名优秀的工程管理者"的资源清单。

README 的标题是 "200+ Resources to become a great engineering leader"，覆盖软件工程、系统设计、数据工程、领导力、管理，一直到 AI、产品与商业。每个主题下大致按这几类分列：

| 分类 | 内容形态 |
| --- | --- |
| List of books | 书名 + 作者（无链接，需自行搜索） |
| List of blogs | 公司工程博客（Meta、AWS、Netflix、Google、Uber、Stripe、Cloudflare……） |
| List of newsletters | 各主题 newsletter，标注作者 |
| People to follow on LinkedIn | 人名 + LinkedIn 链接 |
| Articles | 链接到具体文章 |

**作者给出的使用方法本身是这份清单里最该记住的部分**：不要一次全学；先对自己的现有技能做一次复盘，找出最需要补的领域，然后**一次只挑几个资源**做深挖，而不是把它当成任务清单刷完。

清单里提到的具体书目相当经典，例如系统设计类收有 *Designing Data-Intensive Applications*（Kleppmann）、*System Design Interview*（Alex Xu）、*Patterns of Enterprise Application Architecture*（Fowler）、*Understanding Distributed Systems*（Vitillo）、*Site Reliability Engineering*（Google SRE 团队）等；管理类收有 *The Making of a Manager*（Julie Zhuo）、*The Five Dysfunctions of a Team*（Lencioni，作者个人最爱）、*The Manager's Path*（Camille Fournier）、*Think Again*（Adam Grant）等。

## 用法要点

- README 全文就是清单本身，**可以直接在 GitHub 页面按目录跳读**。
- 书目的条目**只有书名与作者、没有直达链接**，需要用书名自行搜索（作者有意保持清单轻量）。
- 博客、newsletter、人物、文章这几类**带外链**，可直接点开。
- 作者在开头指向了自己写的两篇文章作为"入口"：一篇讲"如何判断自己该补什么技能"，一篇讲"进入工程领导层的完整路线图"，都在他的 newsletter `newsletter.eng-leadership.com`。

## 使用前需要注意

- **这是"目录"不是"教材"**：它不解释任何概念，价值全部来自**选择与分类**。不要指望打开就能学到东西，真正的学习动作在清单之外。
- **有自我推广成分**：开头推荐的路线图与"如何选资源"文章、以及 management 分类里的大量 newsletter，来源都指向作者本人或其社区。清单整体质量不错，但**"作者自家产品占比较高"这一点应知情**。
- **无许可证**：仓库未声明许可。**转载整份清单、或把它做成自己的产品内容前，应先征求作者同意**；个人阅读与收藏不受影响。
- **大量外链会漂移**：博客会关停、newsletter 会换域名、LinkedIn 链接会失效，**长期看清单会比引用它时更早过期**。
- **时效性**：标题写的是"2026 and beyond"，但清单是逐年累加的，部分内容的"当下最佳"属性会随时间衰减。
- **与个人处境的匹配度**：它面向的是"想成为 engineering leader"的路径；如果你当前只想提升纯技术深度，系统设计之外的类别（领导力/管理/组织）可能用不上。
