# goutoujunshi：先接住情绪、再给策略的 Codex 恋爱军师

> 一句话值得记住的取舍：它不替你回消息，而是把"**情绪承接 → 事实 / 推测 / 未知分离 → 关系判断 → 可执行下一步**"做成一套跨学科知识库 + 一个 Codex Skill；知识面很宽（关系心理、人格情绪、约会沟通、性学、婚姻家庭、法律安全、社会人文、恋爱哲学），并把"**同意与退出权不可绕过**"写成硬原则。想研究"把一整个知识领域编译成一个 Agent 技能"这种形态时值得再看。

## 核心结论

**事实：它是一个 "Codex Skill"，不是一个独立 App、也不是 MCP 服务器。** 仓库核心是 `SKILL.md`（行为与路由内核）+ `agents/openai.yaml` + `references/`（知识库）+ `documentation/` + `scripts/`。脸书式安装很轻：README 给的安装方式就是**把一段口令发给你的 AI 助手**，让它把公开仓库下载并安装为本地 Skill。

**它想解决的具体问题**：常见恋爱建议只有两个答案——"勇敢去追"或"赶紧分手"。它的做法是**先接住情绪，再把事实、推测和未知拆开**，同时看心动、现实条件、互惠、风险、机会成本和长期选择权，最后给出一个**可执行**的下一步（一句能直接发送的话、一次具体邀约、第一次见面安排，或一段可复盘的对话演练）。

**它不只是话术库，有两条"边界"设计值得记：**

1. **素材来源与事实边界**：能读聊天截图、导出文本和用户转述，并**区分聊天 / 转述 / 通话 / 线下互动**，减少"把文字聊天脑补成线下现场、把推测写成事实"。
2. **同意门禁 + 可撤销的本地记忆**：跨任务复用档案前**单独征询一次**是否允许在本机保存精简档案；`scripts/memory_store.py` 负责"同意门禁、限量记忆、撤销与删除"。拒绝保存不影响正常使用。

## 一条回答是怎么产生的

README 给的分析链路（这是它最想强调的部分）：

```text
用户叙述
  → 情绪落地
  → 建立本人及目标对象档案
  → 分离事实／推测／未知
  → 检索当前情境所需知识
  → 比较互惠、现实、风险与机会成本
  → 给出明确首选建议和理由
  → 生成行动、话术、观察窗口与停止条件
```

长期记忆与 ChatLab 只在**用户同意或提供相应资料**时按需使用，**不改变这条核心分析流程**。

## 它自己声明的设计原则（六条）

1. **先接住人，再解决事**——情绪没被看见时，最正确的建议也可能无法执行。
2. **行为比标签可靠**——不凭 MBTI、性别或一次聊天记录替对方读心。
3. **互惠比追到更重要**——减少内耗、保留尊严与未来选择权同样是成功。
4. **策略必须说明代价**——可以讨论撒娇、推拉、节奏和表达包装，但同时交代适用条件与长期成本。
5. **同意和退出权不可绕过**——明确拒绝不是需要破解的障碍。
6. **危险情境先保安全**——暴力、胁迫、跟踪、诈骗和自伤风险不能用普通恋爱话术处理。
