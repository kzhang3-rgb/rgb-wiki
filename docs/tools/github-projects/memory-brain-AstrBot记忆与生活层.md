> 记录这套 AI 记忆工程的架构分层、作者自报的参考数据，以及它自我声明的边界。未安装使用。

## 核心结论

一套给 AstrBot 聊天机器人补长期记忆、情绪和生活层的插件集合。作者自己定性为"不是新算法，是一套可落地的工程整合"。

值得记录的主要是两点：一是把记忆拆成五类、检索走五路混合、并单独做了遗忘治理，这比常见的"接个向量库"完整得多；二是用硬约束保证增强功能不覆盖原有人格。

## 它在做什么

按作者的说法是五件事：

1. **记忆**：事件、事实、反思、技能、道理，五种分开存。
2. **检索**：向量 + 关键词 + 实体图谱 + 重要性 + 新鲜度，五路混合。
3. **遗忘**：衰减、归档、相似合并、冲突检测、体检。
4. **情绪**：PAD 三维 + 标签，有上限、有半衰期、不主导判断。
5. **生活**：没找它时也会看书、刷视频、午睡，笔记回流到记忆。

第 3 点是最少见的部分——多数记忆方案只做写入和检索，不做遗忘和冲突处理。

## 不覆盖人格的硬约束

这是作者的显式设计约束，四条规定：

- 人格文件**只读**，所有增强都是往 `system_prompt` 追加"注入块"。
- 每个注入块带 marker，重复注入先删旧块，避免叠加。
- 每个模块一个开关，默认关闭，关掉后行为和原来一致。
- 生活层只写自己的目录，不碰人格和聊天数据。

这种"追加式、可开关、可回退"的处理方式，比自己改人格文件更稳妥，也适合借鉴到其他机器人增强场景。

## 仓库结构

```text
plugins/   四个 AstrBot 插件
  astrbot_plugin_memory_brain       记忆库
  astrbot_plugin_persona_state      情绪 / 好感 / 识海
  astrbot_plugin_human_style_guard  发送前清洗
  astrbot_plugin_self_style         自我档案 / 语气样例
life/      生活层（独立进程，可选）
docs/      框架图、设计说明
eval/      检索评估集（示例）
tests/     单元测试（不需要 AstrBot）
tools/     评估脚本
```

## 安装

记忆与情绪部分：把 `plugins/` 下四个目录放进 `AstrBot/data/plugins/`，然后重启。

```bash
pip install faster-whisper pilk
```

这两个依赖是可选的，用于语音转写。embedding 需要自己配，默认读插件配置里的 `embedding_provider_id`，没配就退化成关键词检索。

生活层是可选的独立进程：

```bash
cd life
python life_loop.py --once
python life_loop.py --send
```

`--once` 是干跑，`--send` 是常驻。不配环境变量也能运行，只是不会刷手机和发消息。

作者建议的开启顺序：先只开写入不开注入，跑一天看摘要质量；再私聊开注入，然后群聊；最后接情绪层；并自建 20–40 条评估集，改一次跑一次。

## 参考数据（作者自报）

| 指标 | 参考值 |
| --- | --- |
| 单轮上下文 | 1.5–1.8 万 token，其中记忆注入约 300 token（约 2%） |
| 记忆规模 | 每天 60 条 → 一年 2.2 万条；十年 22 万条，约 2.4GB |
| 实际占用 | 开启 180 天清理时稳定在 100–200MB |
| 检索延迟 | 当前规模 p50 约 18ms；10 万条以上建议加 ANN 索引 |
| 成本 | DeepSeek 约 2–4 分/轮；一天 100 轮约 2–4 元；本地模型为 0 |

仓库自带评估集和脚本（`python tools/eval_memory.py`），作者在自建的 40 条中文问法上给出的结果是 recall@1 88%、recall@3 100%、MRR 0.938、p50 18ms。

作者自己的结论是："存储不是瓶颈，保留策略才是。"对应地，十年不用换硬件，想记更久就关掉 180 天清理。

**以上数据均来自作者 README，作者也注明是参考值而非承诺。** 评估结果与模型、数据强相关。

## 使用前需要注意

- **项目非常新**：创建至今两天、3 次提交、25 Star，没有第三方长期验证。
- **性能与效果数据是作者自报**，README 里写的是"参考值，不是承诺"，评估集是作者自建的 40 条中文问法。
- **AGPL-3.0 是传染性协议**：插件作为 AstrBot 的衍生作品沿用同一协议，如果要对外提供服务，需要一并开源。
- **会写入本地 SQLite**，内容包括聊天记录派生的记忆，注意备份与隐私。
- **依赖 AstrBot 本体**；embedding 未配置时会退化为关键词检索，效果会打折。
- 我未安装使用，实际效果和稳定性均未验证。
