# lexfridman-cn：Lex Fridman 播客中文站

> 记录一个"把 506 期播客变成可读、可搜、可订阅的中文站"的静态站生成项目，以及它把版权边界写清楚的方式。第一句先记清三件事：**MIT 只覆盖代码，中文精读与元数据不受 MIT**；**它靠 AI 把访谈改写成中文长文导读（不是翻译）**；**仓库不含也不分发任何音频、视频与英文文稿，全部直链官方源**。

- 状态：草稿
- 最近核验：2026-11-03（阅读中英文 README 全文、提交记录与 GitHub API 元数据，并用默认分支 `main` 的 commits 接口复核活跃度；未 clone、未运行构建脚本、未访问站点正文、未核对任何精读的翻译质量）
- 适用范围：**全量构建**任意平台 Python 3 即可（纯标准库）；**精读批产与自动追新**依赖 macOS（钥匙串、`mlx-whisper`）

## 核心结论

这是一个"二次创作型导航站"：把 Lex Fridman Podcast 的 506 期访谈，变成**一期一个独立 URL 的中文页面**，配官方音频/视频直链、中英双语标题、可跳播的英文文稿，以及一个全文搜索。

它真正特别的地方有两处：

**① "中文精读"不是翻译，是 AI 改写。** README 自己划得很清楚：*"AI 基于完整访谈改写的长文导读，不是机器翻译，是「替你先听一遍」的深度转述"*。也就是说，**你读到的中文内容是一次基于完整访谈的二次创作**，而不是原话的忠实转换。作者对此的处理方式是：把管线也写进 README（`tools/gen_zh.py` 常驻批产，内置"禁句式校验（机器翻译腔）"、不合格带反馈重试、多模型按质量动态排序），并在免责声明里承认"AI 生成、可能存在偏差，表述以原始访谈为准"。**这个态度值得借鉴：它没有把 AI 生成的内容伪装成翻译。**

**② 版权边界被显式拆成三段。** 这在同类"搬运型站点"里很少见：

- **代码** → MIT；
- **`site/zh/` 中文精读与元数据** → **不适用 MIT**，转载需署名并链接对应原文页面；
- **英文文稿（官方 / 存档 / ASR）** → 版权归 Lex Fridman、嘉宾与制作方，**仓库不包含、不分发**，管线在本地自行获取或转写。

README 还写明"不接受与托管媒体文件相关的改动——这是项目的版权边界"。**这条比许可证本身更有信息量：它把"什么不能进仓库"作为项目规则固定下来。**

第三个值得记的事实是**口径滞后**：README 正文与 `site/zh/` 描述都写"463+ 篇中文精读"，但提交记录显示 **2026-10-25 已是"第 506 篇落地、精读全覆盖"，2026-10-28 又更新为 507**。**README 里的数字落后于仓库实际状态**——与之前记录过的多起同类情况一致，**自述数字要以 git 记录和实际文件为准**。

## 它能做什么

**站点能力（README 表格）**

| 能力 | 内容 |
| --- | --- |
| 中文精读全文 | AI 深度改写导读，批产管线持续更新，RSS 全文可订阅 |

| 全文搜索 | 全半角/标点归一化、多词 AND、加权排序（嘉宾 > 标题 > 简介）、期号精确命中、关键词高亮、`/` 或 `⌘K` 唤起、`?q=` 可分享 |

| 英文文稿 | **三梯队供给：官方文稿 > 本地 Whisper ASR > 存档**；时间戳点击跳播、文稿内 `Enter`/`↑↓` 跳转 |
| 订阅与 SEO | RSS 最新 20 期精读全文（真实 enclosure 长度、ETag/304）、JSON-LD（含 SearchAction）、sitemap、**`llms.txt`** |

**自己构建（README 给了"已验证"字样）**

```bash
git clone https://github.com/joeseesun/lexfridman-cn.git
cd lexfridman-cn
python3 tools/build.py                 # 全量构建到 site/（纯标准库，零第三方依赖）
python3 -m http.server 8123 -d site    # 打开 http://127.0.0.1:8123
```

README 标注：**已验证（2026-10-19）**——`python3 tools/build.py` → 506 个单集页 / sitemap 508 条 / RSS 最新 20 期全文；README 里的截图即本地构建产物。**元数据与精读全文都入库，clone 下来即是全量数据**，不需要额外的数据源。

**内容管线（README 的流程图，摘要）**

```text
官方 RSS (lexfridman.com/feed/)
   │ tools/sync_new.py   每日对账：新期 → 元数据 → 标题翻译 → 按三梯队补文稿
   ▼
tools/lex-master.json（506 期元数据、入库）
   │ tools/gen_zh.py --watch   中文精读批产（禁句式校验、带反馈重试）
   ▼
site/zh/*.html（精读全文、入库）
   │ tools/build.py   506 个单集页 + sitemap + llms.txt + RSS
   ▼
site/ ──rsync──► 任意静态主机
```

- `gen_zh.py` 是**系统提示词驱动的长文改写**，多模型路由按质量动态排序，不合格带反馈重试。
- 自动追新默认走作者自建的 [Magpie](https://magpie.qiaomu.ai/v1) LLM 网关（可改 `BASE_URL` 换成任意 OpenAI 兼容端点），网关 key 存 **macOS 钥匙串**（原文强调"不落盘、不进环境变量"）。
- 定时化：`crontab` 每日跑一次 `sync_new.py` 即可全自动追新。

## 使用前需要注意

**① "中文精读"是 AI 二次创作，不是翻译。** 想引用某个观点时，**应以原始访谈为准**；README 与免责声明都这么写。使用这类内容时应保留"这是 AI 改写"的前提。

**② 许可证只覆盖一部分，转载前要分段看。** MIT 只覆盖代码；`site/zh/` 的精读与元数据**不在 MIT 范围内**，作者要求转载时**署名并链接原文页面**；英文文稿的版权归 Lex Fridman 及其嘉宾、制作方，**仓库既不含也不分发**。若你要复用本仓库的任何内容，**三方（代码 / 精读 / 文稿）的条件各不相同**。

**③ README 的数字落后于仓库实际。** README 写"463+"，但提交记录显示精读已达 506→507 篇（2026-10-28）。**引用规模时以仓库文件与 git 记录为准**。

**④ 仓库极新，且完全依赖持续日更。** 2026-10-18 创建（核验时约两周），价值来自"每天有新期就补上"。一旦流水线停摆（例如作者的 LLM 额度、网关或宿主出问题），站点会停在最后一期；**核验日之后的追新状态需要重新确认**。

**⑤ 内容管线偏向作者自有基础设施。** 精读管线默认走 Magpie 私有网关（可替换），追新依赖 macOS 钥匙串与 `mlx-whisper`，部署目标是脚本里的 `rsync` 路径。也就是说，**"全量构建站点"门槛很低（Python 3 即可），但"自己跑完整管线"门槛不低且与作者环境耦合**。

**⑥ 站点与仓库都属同一作者的生态。** README 列出 `qiaomu.ai`、`blog.qiaomu.ai`、`tuijian.qiaomu.ai` 与微信公众号，属于作者的内容矩阵。这不影响项目质量，但记录在此以便理解其性质。

**⑦ 未验证的部分。** 我没有 clone、没有运行构建、没有访问站点正文、**没有核对任何一篇精读的准确性或风格**。上文全部来自 README（中英文两版一致）、提交记录与 API 元数据。**"AI 改写"内容的质量与偏差风险，需要你自己抽样判断。**
