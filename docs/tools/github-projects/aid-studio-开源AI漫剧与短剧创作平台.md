# aid-studio：开源 AI 漫剧 / 短剧 / 电影 / 漫画创作平台

> 一句话定位（README 自述）：**"开源 AI 漫剧、AI 短剧、AI 电影与 AI 漫画创作平台"**——覆盖**剧本、角色场景、智能分镜、图片与视频生成、配音及成片预览**，**多模型接入**、**可自行部署**（路线图里还有"无限画布、导演台"）。它最值得记的不是功能列表，而是三件事：① 它把**一条完整的短剧/漫剧生产流水线**（从剧本到成片预览）做成了自托管平台，而不是单点生成工具；② 它把**平台侧的重活**也一起做了——**多供应商编排、统一任务系统（队列/并发/进度/重试/补偿）、计费（余额冻结 + 支付宝/微信）、用户账号（短信/邮箱/微信扫码 + 实名认证）、后台管理、在线升级**；③ **它是"开源核心 + 自备各供应商 API"模式**——代码 MIT、平台可白嫖自己部署，但**每个模型的调用费要你自己掏**。

## 核心结论

**一句话定位（README 自述）**：**开源 AI 漫剧 / AI 短剧 / AI 电影 / AI 漫画创作平台**，支持从**剧本 → 角色场景 → 智能分镜 → 图片与视频生成 → 配音 → 成片预览**的完整创作流程，**多模型接入、可自行部署**。

**三个最值得记的点：**

1. **它做的是"整条产线 + 平台"，不是单点生成**（README 自述）：
   - **三大创作方向**：**AI 漫剧 / 短剧**、**AI 电影 / 短片**、**AI 漫画**。
   - **核心创作能力**：剧本、角色与场景、**智能分镜**、图片生成、视频生成、配音、**成片预览**。
   - **受控模型调用**（README 强调的工程点）：**固定参数 + 运行时推理选项 + 请求映射按显式优先级合并**，可在**提交供应商前就拒绝配置错误**——这是把"多模型接入"做得可管理的关键，而不是简单把 key 塞进配置就完事。
2. **平台侧的重活它也一起做了**（README 自述）：
   - **多供应商编排 + API 网关配置**
   - **统一任务系统**：队列、并发、进度、**重试、补偿**
   - **视觉一致性**（跨镜头/跨图角色与画风一致——短剧/漫剧的刚需）
   - **计费**：按模型 / SKU 计费、**余额冻结**、**支付宝 / 微信支付**
   - **用户账号**：**短信 / 邮箱 / 微信扫码登录**、**实名认证**、邀请激励
   - **后台管理 + 生产运维 + 在线升级**（滚动更新与回滚，靠 `aid-updater`）
3. **"开源核心 + 自备供应商 API"是它的商业模式**（README 自述）：
   - 代码 **MIT**，**平台可自己部署**；官网 <https://www.aidstudio.com.cn/>。
   - **但模型调用要你自己接、自己付费**：你需要**自备各供应商的 API 凭证**，**按各家的量付费**——平台本身不替你承担生成成本。
   - 依赖 **RuoYi-Vue**（`NOTICE` 明确声明，gitee.com/y_project/RuoYi-Vue，MIT）。

**个人判断（未验证）**：它是"**把 AI 内容生成从'单点工具'做成'一整套可运营的产品'**"的典型——功能面（漫剧/短剧/电影/漫画 + 配音 + 分镜 + 成片预览）覆盖得很全，**且把计费、支付、实名、任务队列这些"要上线才需要"的东西也做进了开源仓库**。这类项目的取舍很清晰：**上手门槛高（要装中间件、配数据库、接多个模型供应商），但换来的是"可控、可自部署、数据在自己手里"**。**风险见下**（需自备凭证与费用、安装脚本执行远端脚本、含敏感模块、素材版权自担）。

## 部署要点（README / `deploy/README.md`）

- **三种安装方式**：`install`（脚本）、`install-docker`（容器）、`install-manual`（手动）。
- **安装脚本的下载策略**：**先取 Gitee、失败回退 GitHub**（`https://gitee.com/gzxx-2025/aid-studio/raw/master/deploy/aid.sh`）——**即"一键安装"实际执行的是远端脚本**，自行评估。
- **最低资源**：**2 核 / 4 GB / 40 GB**（RocketMQ 关闭、中间件同机部署的前提下）。
- **安全闸门**：配置未确认前**不拉代码、不构建、不初始化数据库、不启动服务**。
- **管理命令**：`sudo aid default|status|logs|config|restart|update|progress|rollback|backup|mysql|uninstall --keep|--purge`。
- **Docker 模式**：支持**内置 / 外部 MySQL 5.7**、Redis、**可选 RocketMQ**、**可选 HTTPS**。
- **首次登录后必须立即改管理员密码**（README 明确提示）。

## 使用前需要注意

- **旧地址会跳转**：`gzxx-2025/aid-studio` 已重命名为 `shijue-aid/aid-studio`，用旧 URL（含 raw 文件）会跳转；引用时建议统一用新地址。
- **必须自备各供应商的 API 凭证，生成费用按量自付**：这是它"开源"之外的真实成本——**平台免费，生成不免费**。接哪几家、费用多少，取决于你配了哪些供应商与用量。
- **安装脚本会执行远端脚本**：`aid.sh` 从 Gitee（失败回退 GitHub）拉取后执行。**在服务器上跑"curl | sh"式安装前，先自己读一遍脚本**，确认它做了什么、会改哪些系统项。
- **仓库含计费 / 支付 / 实名 / 短信等敏感模块**：**支付宝 / 微信支付、短信、实名认证**都在其中。**若对外运营，合规责任在你**（支付资质、实名数据、隐私政策、短信通道等需自行落实）——README 不承担这部分。
- **素材版权自负**：生成/上传的剧本、角色、图片、视频、配音**是否侵权、能否商用，由使用者自行保证**；平台本身不替你解决版权问题。
- **部署门槛不低**：需要 **MySQL 5.7 + Redis（+ 可选 RocketMQ）**，且要接多个模型供应商；**2 核 / 4 GB 是最低线，不是舒适线**。
- **许可证要连 `NOTICE` 一起看**：代码 MIT，但**内含 RuoYi-Vue 的代码**（同为 MIT）；**再分发时请保留 `NOTICE` 中的第三方声明**。
